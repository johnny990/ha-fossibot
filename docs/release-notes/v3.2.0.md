# v3.2.0 — Controls for protocol V1 stations (F7200)

v3.1.0 made protocol V1 stations readable; this release makes them
controllable. Every write below was checked byte for byte against frames the
BrightEMS app itself sent to an F7200 over the local MQTT broker.

## ✨ Added

**V1 write path.** The app writes protocol V1 devices with a frame the V0
document does not describe, `[addr, func, reg, 0x00, count, value_hi,
value_lo, …, crc]`: function 5 for the state word (input register 75; the app
reads the word, flips one bit and writes it back whole) and function 6 for
holding registers, with several consecutive words allowed in one frame.
`get_write_modbus_v1()` encodes it behind an allowlist
(`WRITABLE_REGISTERS_V1`); the connector's new `write_v1` command refuses to
run against a device that is not on profile V1.

**New entities on V1 devices**

- Switches, all bits of the state word unless noted: AC Output (bit 4),
  DC & USB Output (bit 3, one bit covers both), AC Silent Charging (bit 6),
  Buzzer (bit 7), AC Custom Charge (bit 12), Charge Schedule 1-3 (input
  register 83, bits 0-2).
- Select: DC Input Type, PV mode / DC mode (bit 5).
- Numbers: DC Input Charging Current Limit (holding 23, 1-20 A, capped by the
  maximum the device reports), Discharge Lower Limit (26, 0-50 %), AC Charging
  Upper Limit (27, 60-100 %), Screen Rest Time (25), AC / USB / DC Standby
  Time (24 / 29 / 30), Whole Machine Unused Time (28).
- Diagnostic sensors Charge Schedule 1-3, showing each custom charge window
  the way the app does, e.g. `23:00-07:00 to 90 % Daily`.

**Action `fossibot.set_charge_schedule`.** Writes one custom AC charge window
(slot 1-3, start and end time in 10-minute steps, an energy amount *or* a
target SoC, repeat daily or on chosen weekdays, optional enable) as three
holding words in one frame, exactly as the app's "send to device" does. The
window packing: time word = end hour / end minute ÷ 10 / start hour / start
minute ÷ 10 in 5+3+5+3 bits, amount word = kWh × 10 in the high byte and
target SoC in the low byte, repeat word = weekday mask with Sunday as bit 0.

## 🔄 Changed

**Entity naming.** Entities now carry only their own name
(`has_entity_name`), so Home Assistant prefixes the device name and renaming
the device renames every entity with it. Entity ids of existing installs are
unchanged; new installs get ids such as `switch.f7200_ac_output`.

## ⚠️ Notes

- A state-word write carries every other bit as last polled, exactly as the
  app does; a change made from the app in the seconds between a poll and a
  write is overwritten.
- Charge windows store either an energy amount or a target SoC; setting one
  clears the other, as in the app. A window cannot be cleared through the
  action (the firmware encodes "not set" as 0, which is not a valid time pair);
  delete it in the app.
- Still read only on V1: the AC charge level (holding 1) and the grid-tie
  output block (maximum power sold to grid, load following, Simple / Custom
  Grid), which is decoded into sensors only.
- Bits 0-2 of the state word carry balcony-inverter names in the app's table
  and have no known meaning on a station; they are not exposed.

## 🧪 Tests

`tests/test_registers_v1.py` now also covers the bit-flip helper, the frame
layout and CRC against six captured app frames (buzzer, DC & USB, AC output,
schedule enable, two window writes), window encoding and its refusals, and the
allowlist refusals (limits, protocol version, factory reset, non-state input
registers, multi-word writes outside window bases).
